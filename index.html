Models 图谱量化版对比quantisation comparison

你决定用哪个模型之后，真正要面对的问题是：同一模型有几十个量化版，我该下哪一个？
本站只回答这一个问题——不评模型强弱，只帮你选对量化版。Once you have picked a model, the real question is: a given model has dozens of quantisations — which one do I download?
This site answers only that. It does not rank models against each other; it helps you pick the right quantisation.

收录范围：只收开放权重、可本地部署的开源模型（HF 上有公开权重的 MoE 与 dense模型）。闭源 / API-only 模型不在收录范围内——它们没有量化产物，下载和选型的问题不存在。Scope: open-weight models you can run locally (MoE and dense models with public weights on HF). Closed-source / API-only models are out of scope — they have no quantisations, so the download and selection questions do not arise.

先说清楚：这个站的数据怎么来的First, where this site's data comes from

✅ 实测字段Measured fields

直接从 Hugging Face 公开 API 读取的客观数据：文件体积（字节）、上下文长度、架构、许可、下载量、更新时间。Objective data read straight from the Hugging Face public API: file sizes in bytes, context length, architecture, licence, downloads, last updated.

✅ 推导Derived

由实测字段按公开规则算出：每权重比特数（依 llama.cpp 命名标准）、档位归属、显存需求区间。推导规则在Computed from the measured fields by published rules: bits per weight (per the llama.cpp naming convention), tier assignment, VRAM requirement range. The rules are fully published in METHODOLOGY.md 完整公开，任何人可复算。 — anyone can recompute them.

❌ 我们不说的What we do not claim

哪个量化质量更高、哪个更快、哪个模型更强——这些需要实测，本站不跑 benchmark，所以不装作知道。凡我们给出的主观判断，一律显式标注「我们的口径」。Which quantisation is higher quality, which is faster, which model is stronger — these need measurement. This site does not run benchmarks, so it does not pretend to know. Every subjective judgement we do offer is explicitly marked as our own reading.

怎么用这个站How to use this site

  1. 先看你有多少显存。这是唯一的硬约束，8GB 和 24GB 能跑的档位完全不同。显存撑不下时看同一张表的「系统内存 / 多卡」两栏——纯 CPU 或多卡张量并行也是可行路线。Start with how much VRAM you have. It is the only hard constraint — the tiers that fit in 8GB and 24GB are entirely different. If VRAM is the limit, look at the "system memory / multi-GPU" columns in the same table — CPU-only or multi-GPU tensor parallel are viable routes.
  2. 在 B 区块查速查表。直接给出「这个显存 / 内存档位该用哪个量化档」，体积是实测值。Use the cheat sheet in block B. It maps a given VRAM / memory budget to the tier to use, with measured sizes.
  3. 在 C 区块横向对比量化者。看谁档位全、谁带 imatrix、谁在跟进更新。Compare quantisers side by side in block C. See who covers the most tiers, who ships imatrix, and who is keeping up with releases.
  4. 在 D 区块看单档详解。七个字段说清每个变体是什么、差在哪、什么时候该选它。Read the per-tier detail in block D. Seven fields spell out what each variant is, how it differs, and when to pick it.
  5. 下载前先读许可。非宽松许可的，页面会标出来；量化仓没单独声明许可的，页面会写明「继承自基座」，原文链接就在旁边。Read the licence before downloading. Non-permissive licences are flagged; where a quant repo declares none, the page says "inherited from base" with the original link right beside it.
