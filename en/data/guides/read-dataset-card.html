How to read a dataset card

Practitioner methodology · key facts carry official sources

A dataset card is not an advertisement. Read the licence, scale definition, languages and access method first, then ask what task it fits. If one of the four is missing, do not train on it directly.

← Section indexModels home

Licence before download count

The licence decides whether you can use, modify, commercialise and redistribute the data, and whether modifications must stay open. CC-BY variants usually require attribution; CC-BY-SA is share-alike; ODC-BY requires attribution; Apache-2.0 and MIT are more permissive but the package licence and the original-content licence are still two different things.

Scale: tokens, samples or raw web pages

15T tokens, 3T tokens and 30T raw tokens are not the same unit. Token counts depend on the tokenizer; sample counts depend on deduplication; raw web volume is not cleaned training volume. When comparing datasets, normalise to one unit and state “before / after cleaning”.

Languages, format and access

Uneven language coverage changes model behaviour. A multilingual dataset dominated by English can underfit smaller languages unless you sample by language. Format determines the cleaning pipeline: JSONL streams more easily than Parquet; URL metadata may require downloading the source. A gated dataset may require accepting terms; “can download” is not “can redistribute”.

Task fit and bias notes

Pretraining corpora, SFT data, preference data, evaluation sets and RAG corpora are different products. Check what the card says about collection, consent, filtering, known bias and prohibited uses. Then run a small sample through your own cleaning and training pipeline before committing to the full set.
