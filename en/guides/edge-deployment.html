Edge deployment: bandwidth, quantisation and power

Practitioner methodology · key facts carry official sources

An edge device is not a small server. Memory bandwidth, power and cooling become the ceiling before compute does. Accept on tokens per second, peak memory and sustained power — not on parameter count alone.

← Section indexModels home

Bandwidth hits first

Decode speed on an edge device is usually limited by memory bandwidth, not by TOPS. A model that fits in memory can still be too slow if every token requires reading the full weight set. Measure tokens per second on the target device and batch size; datasheet peak numbers rarely survive real thermal limits.

Quantisation decides fit

4-bit weights can cut memory by roughly 4x versus FP16, but the cost moves into accuracy, kernel support and dequantisation overhead. Test the exact quantisation format the runtime supports, not a generic “4-bit” label. Keep a small held-out set for quality regression after quantisation.

Unified vs discrete memory

Unified-memory devices share one pool between CPU and GPU, which can fit larger models but reduces effective bandwidth under contention. Discrete GPUs have dedicated memory but pay for copies over PCIe or Thunderbolt. Profile the whole pipeline, including preprocessing and postprocessing.

Power and cooling are part of the spec

Sustained clocks drop when a fanless case or a small power supply cannot remove heat. Measure tokens per second after 10–15 minutes of continuous load, and record wall power. A device that is fast for one minute and throttles afterward is not a deployment target.
